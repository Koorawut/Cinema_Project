1. System Architecture — ผังระบบภาพรวม

ระบบแบ่งเป็น 3 ชั้น: หน้าเว็บ (front-end) คุยกับ API กลางบน Vercel ซึ่งต่อฐานข้อมูล PostgreSQL และคลาวด์เก็บรูป ทุกคำขอผ่าน API เสมอ — หน้าเว็บไม่ติดต่อฐานข้อมูลโดยตรง

จุดสำคัญของสถาปัตยกรรม

  • รอบฉายคำนวณจากข้อมูล: ไม่มีตาราง showtimes — คำนวณจาก "ตารางฉายต่อเรื่อง" ในตาราง movies (hall_id, date_start, date_end, periods) เป็น id รูป st-{movieId}-{YYYY-MM-DD}-{morning|afternoon|evening}
  • กันจองซ้อนที่ระดับฐานข้อมูล: booking_seats UNIQUE(showtime_id, seat_id) + insert การจอง/ที่นั่งใน SQL เดียว → ชนตอบ 409 พร้อมรายชื่อที่นั่ง (P-03)
  • เวลาทั้งหมดของ server: ISO 8601 +07:00, "วันนี้" คำนวณที่ server (P-11) — client ไม่เชื่อนาฬิกาเครื่องผู้ใช้
  • ราคาคำนวณที่ server เสมอ: client ส่งเฉพาะ showtimeId/seatIds/promoCode — server คิดเงินจากข้อมูล DB และกติกาคูปองเอง
  • นโยบายลบ: ลบบัญชี/หนัง → การจองไม่หาย (SET NULL + snapshot ชื่อ/ราคาใน bookings); ห้ามลบหนังที่มีการจองอนาคต (409, P-16/P-18)
